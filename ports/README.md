# Waveshare AMOLED 1.8 V1 — экспериментальный порт

**Статус: первый этап реализован в едином PR #2; железа нет,
аппаратная проверка не выполнялась. Не готовая прошивка.**

Только V1: SH8601 + FT3168. **Не устанавливать на V2 CO5300/CST820.**

## Что сделали

- `ports/amoled_v1.py`: независимый аппаратный мост, который ожидает
  нативный драйвер MicroPython `amoled.QSPIPanel/AMOLED`. Он не заменяет
  основную IPS-реализацию `hw.py`.
- Временная совместимая область 240 × 284 в центре физического
  экрана 368 × 448: **x=64..303**, **y=82..365**.
  Сохраняются размеры, русский шрифт и меню оригинальной игры;
  чёрные поля пока остаются вокруг. Позднее — масштабирование UI.
- `FT3168Touch.ler()` читает I²C 0x38 и переводит касания физических
  пикселей в игровые координаты. Пустые поля и отпускание игнорируются.
  При наличии GPIO21 вход I²C не опрашивается, пока палец не касается
  экрана: это снижает число NACK спящего FT3168.
- Защита по I²C: **0x20 TCA9554**, **0x38 FT3168** и запрет при
  обнаружении **0x15 CST820**. При холодном старте FT3168 может
  удерживаться в reset, тогда разрешение отпустить его допускается
  только с явной опцией `verified_v1=True` после проверки маркировки.
- Управление панелью/сенсором через TCA9554:
  **EXIO0 — reset SH8601, EXIO1 — питание AMOLED, EXIO2 — reset тача**.
  Остальные биты регистров сохраняются.
- Пример `ports/amoled_v1_smoke.py` — отдельная ручная проверка
  цветных полос и сенсора, **не вызывается игрой автоматически**.
- `ports/preview_amoled_v1.py` — компьютерный предпросмотр именно
  временного 1:1 отображения, не эмуляция чипа.
- `tests/test_amoled_v1.py` — имитация QSPI, сенсора, TCA9554,
  проверка соответствия координат, байтов RGB565 и отказ при V2.

## Разводка V1

| Функция | Контроллер или вывод |
|---|---|
| Экран | SH8601, QSPI 368×448 |
| Тач | FT3168, I²C 0x38 |
| Экспандер | TCA9554, I²C 0x20 |
| I²C SCL/SDA | GPIO14 / GPIO15 |
| QSPI CS/CLK | GPIO12 / GPIO11 |
| QSPI DATA0..3 | GPIO4 / GPIO5 / GPIO6 / GPIO7 |
| Touch IRQ | GPIO21 |
| LCD RESET / AMOLED POWER / TP RESET | TCA9554 EXIO0 / EXIO1 / EXIO2 |
| GPIO13 | НЕ считать аппаратным LCD_RESET без отдельного подтверждения |

Источник: [официальная Waveshare](https://docs.waveshare.com/ESP32-S3-Touch-AMOLED-1.8),
[собственный конфиг дободу](https://github.com/dobodu/Lilygo_Waveshare_Amoled_Micropython/blob/main/examples/config/WS_180_AMOLED.py),
[отладка V1 и проверка TCA9554 на оборудовании](https://github.com/rbirkby/waveshare-touch-amoled-1.8-fluidparticles).
В стороннем MicroPython-примере GPIO13 используется как reset;
другой источник, проверенный на оборудовании, указывает на EXIO0.
Поэтому текущий экспериментальный мост использует **EXIO0** и оставляет
вопрос окончательной совместимости нативного драйвера открытым.
Код внешней библиотеки не копировался; у неё лицензия MIT.

## Почему V1 пока нельзя прошить обычным установщиком

SH8601 требует QSPI-транспорт (четыре линии данных). Обычный драйвер
ST7789 и обычная версия MicroPython с `machine.SPI` не заменяют
нативный QSPI-стек. В проект пока **не включён** совместимый
проверенный бинарный образ MicroPython с модулем `amoled`.

`install.sh --board amoled-v1` по-прежнему намеренно отказывает.
Нельзя использовать IPS `deploy.sh` для V1, чтобы не стереть и не
испортить заводскую прошивку. Для первого теста когда-нибудь потребуется
подтверждённая V1 и точная сборка стороннего нативного драйвера.

## Без оборудования: как посмотреть результат

Откройте [последний успешный GitHub Actions](https://github.com/Medvedolog/medvegoshi/actions/workflows/verify-python.yml)
ветки `feature/russian-game-ui` и скачайте артефакт
`medvegoshi-giraffe-preview-and-ips-pack`.

В архиве:
- `qa-amoled-v1/v1-viewport-240x284.png` — **фактическая геометрия
  экспериментального порта**: 240×284 в центре 368×448.
- `qa-amoled-v1/all_expressions.png` — отдельно арт-предпросмотр
  Жирафика, увеличенный для оценки дизайна.
- `qa-ips/` — исходный IPS-предпросмотр и отчёт о ресурсах.

Хостовые тесты:

```bash
python3 -m pip install "Pillow>=10,<13"
python3 -m unittest discover -s tests -p 'test_amoled_v1.py'
python3 -m unittest discover -s zoo/tests -p 'test_*.py'
```

## Память — расчёт, не измерение

- 240×284×2 = **136 320 байт** для штатного `framebuf` игры;
- 368×448×2 = **329 728 байт** для полного нативного RGB565 буфера
  (если выбранная реализация драйвера его выделяет);
- оба буфера вместе — **466 048 байт**, без расходов MicroPython,
  Zoo, драйверов, аудио и мозга. Физических замеров PSRAM/FPS пока нет.

## Нативная сборка MicroPython с SH8601/QSPI — воспроизводимый прототип

Добавлена отдельная [сборка GitHub Actions](https://github.com/Medvedolog/medvegoshi/actions/workflows/build-amoled-v1.yml).
Она **не прошивает плату**, не меняет IPS и не публикует релиз.
При успешной компиляции появляется артефакт `medvegoshi-v1-native-UNTESTED`
с файлом `medvegoshi-amoled-v1-experimental.bin`, `SHA256SUMS`,
`BUILD-METADATA.json`, файлом подготовки и оригинальной MIT-лицензией.
Бинарник **без файлов игры MedveGoshi** и не рассчитан на установку без
дополнительной проверки аппаратной ревизии. Даже успешная сборка не
означает, что SH8601 действительно заработал на устройстве.

Зафиксированные источники:

- MicroPython [v1.28.0, SHA `e0e9fbb17ed6fd06bb76e266ae554784c9c80804`](https://github.com/micropython/micropython/tree/e0e9fbb17ed6fd06bb76e266ae554784c9c80804);
- ESP-IDF [v5.5.2](https://github.com/espressif/esp-idf/tree/v5.5.2), Docker
  `espressif/idf:v5.5.2` с зафиксированным индексом SHA256;
- MIT-драйвер [dobodu/Lilygo_Waveshare_Amoled_Micropython, SHA `97934b7c35b1720a14fd69e4e1322bb5684b9b2c`](https://github.com/dobodu/Lilygo_Waveshare_Amoled_Micropython/tree/97934b7c35b1720a14fd69e4e1322bb5684b9b2c).

Скрипты `ports/build_amoled_v1.sh` и `ports/prepare_firmware.py` скачивают
названные исходники по **точным коммитам**. Последний корректирует
некорректный CMake-файл нативного модуля в отдельной временной копии,
подключает `schrift.c` и включает схему **Flash 16 МБ / Octal PSRAM**.
В наши исходники не импортирован сторонний графический C-код.
Любые изменения расположения файлов или лицензии upstream прерывают сборку.

На Linux с установленным ESP-IDF 5.5.2 (или внутри одноимённого Docker
image) воспроизвести сборку можно командой:

```bash
bash ports/build_amoled_v1.sh
```

Обычные проверки выполняются без компилятора ESP32:

```bash
python3 -m unittest discover -s tests -p 'test_amoled_native_build.py'
```

**Подключение к игре — пока ограничено графикой:**
`ports/v1_game_demo.py` вызывает подлинные `desenho.usar()` и
`desenho.personagem('girafa', ...)` поверх AMOLED-адаптера без копии
`main.py`. Ручной V1 smoke-тест показывает Жирафика после проверки
цветных полос и тача. Полный игровой цикл ещё требует общего HAL
для RTC, QMI8658, ES8311, AXP2101 и кнопок.
