# Карта кода MedveGoshi / Capigoshi

Документ описывает **текущее наследуемое состояние исходников**. Названия Python-модулей и португальские идентификаторы пока не меняются: это часть совместимости с оригиналом. Документация на русском; перенос на AMOLED V1 в разработке.

## Основные модули

| Путь | За что отвечает | Ключевые особенности |
|---|---|---|
| `main.py` | Главный игровой цикл, настройки, время, взросление, сенсорные события, три режима | `passo()`, `principal()`, `acao_pet()`, `atualizar_cerebro()`, `processar_toque()` |
| `hw.py` | Драйверы аппаратных устройств | `Tela` (ST7789), `Toque` (CST816D), `Movimento` (QMI8658), `Relogio` (PCF85063), `Bateria` (AXP2101), `Som` (ES8311/ES7210) |
| `desenho.py` | Все элементы графики | Пейзажи, 10 персонажей, анимация, меню, шрифтовый вывод 8×8, RGB565 |
| `vida.py` | Поведение, реплики, эмоции и движения | `MOVES`, `FRASES`, `FRASES_CHAR`, `V.tocar()`, `V.passo()` |
| `rede.py` | Радиосвязь | Периодическое подключение Wi-Fi для времени/погоды и ESP-NOW для соседних питомцев |
| `portal.py` | Локальный веб-сервер | Подключение к домашней сети через телефон, страницы состояния мозга |
| `companion/` | Обучаемый «мозг» | Сеть импульсных нейронов, параметры потребностей, награды, привычки, симуляторы, тесты |
| `sons/` | Аудиофайлы и загрузчик дополнительных эффектов | RAW PCM 16 кГц / 16 бит / стерео; Pixabay отдельно |
| `previa/` | Предпросмотр игры на компьютере | Настоящая игровая логика + заглушки оборудования; PNG-кадры и проверки |
| `deploy.sh` | Установка на **оригинальный IPS** | Полная прошивка стирает Flash; `--so-arquivos` обновляет файлы |
| `docs/` | Исходные веб-страницы и иллюстрации автора | Не путать с русскими инструкциями в корне репозитория |
| `design_handoff_capigoshi_1c/` | Архив технического задания на визуальный стиль | Оригинальный JS-рендерер и размеры для IPS 240×284 |
| `sdd/` | Исторические технические задания и заметки | Архив проектирования исходного Capigoshi |

## Как проходит один кадр

```text
main.principal()
  └─ main.passo(agora, dt)
       ├─ обновление звука, касаний, BOOT, меню, батареи
       ├─ возраст, сенсоры, Wi-Fi / ESP-NOW
       ├─ режим: Уход / Наблюдение / Прогулка
       ├─ обновление импульсной нейросети (для Наблюдения)
       ├─ vida.passo() → движение, реплика, эмоция
       ├─ сохранение игрового состояния
       └─ desenho.*() → framebuffer → hw.Tela.mostrar()
```

## Интеграционные точки

- **Графика:** `desenho.usar(tela.fb)` получает объект кадрового буфера, который затем обновляет `hw.Tela.mostrar()`. Для AMOLED нужна совместимая графическая обёртка.
- **Ввод:** `hw.Toque.ler()` возвращает координаты; `main.processar_toque()` передаёт их в `pressionar()`, `arrastar()` и `soltar()`.
- **Персонаж:** `vida.nova(id, vt)` создаёт состояние; `vida.passo(...)` вычисляет позу. Рендерер `desenho.personagem()` рисует её.
- **Кормление/игра:** `main.acao_pet(i)` меняет показатели и запускает звук и анимацию.
- **Обучение:** `main.atualizar_cerebro()` вызывает `companion.placa.Ponte`, которая кодирует сигналы, выбирает действие и сохраняет `brain.bin`.
- **Звуки:** `hw.Som.tocar(name)`, микрофон `volume_mic()`; звуковой тракт делит I2S-ресурсы.
- **Интернет:** `rede.passo()` возвращает события погоды, времени, знакомства и подарков.

## Сохранённые данные на плате

| Файл | Назначение |
|---|---|
| `config.json` | Персонаж, режим, параметры времени и звука |
| `capi.json` | Состояние питомца и его возраст (в текущей реализации один активный персонаж) |
| `brain.bin`, `brain.bak` | Весовые коэффициенты нейросети, привязанность, привычки; контроль CRC и резервная копия |
| `wifi.json` | Локальные сетевые параметры — **не добавлять в Git** |
| `clima.json`, `presentes.json` | Кэш погоды и подарков |
| `raiox.html` | Страница визуализации состояния мозга |

Сохранение параметров питомца происходит периодически, а нейросети — примерно раз в 10 минут и при некоторых переходах. Это не заменяет безопасного завершения работы перед отключением питания.

## Нейросеть `companion/`

- `actions.py` — каталог 100 действий и их условия;
- `encoder.py` — превращает датчики, часы, погоду и события в сигналы;
- `snn.py`, `nucleo.py`, `nucleo_viper.py` — вычисления сети;
- `learn.py`, `reward.py`, `relogio.py` — обучение, подкрепление и привязка действий ко времени;
- `drives.py`, `clima.py` — внутренние потребности и влияние погоды;
- `cerebro.py`, `placa.py` — принятие решений, мост к игровой плате, сохранение;
- `expressao.py` — перевод выбранного действия в движение, фразу и звук;
- `testes/`, `sim/` — юнит-тесты и сценарии.

Технические параметры и результаты измерений см. в [CALIBRACAO.md](CALIBRACAO.md).

## Как организовать порт AMOLED V1

Цель: **Waveshare ESP32-S3-Touch-AMOLED-1.8 V1**, дисплей **SH8601 368×448**, касание **FT3168**.

1. Разделить `hw.py` на платформонезависимый интерфейс и реализации IPS/AMOLED, не меняя игровую логику.
2. Проверить загрузку MicroPython с поддержкой QSPI AMOLED; в качестве исследуемой базы использовать [dobodu/Lilygo_Waveshare_Amoled_Micropython](https://github.com/dobodu/Lilygo_Waveshare_Amoled_Micropython).
3. Подключить тачскрин FT3168 и проверить ориентацию, координаты и удержания.
4. Согласовать систему координат с `desenho.py`; сохранить ограничения отображения исходного интерфейса либо масштабировать с переработкой меню.
5. Проверить QMI8658, RTC, ES8311, микрофон и питание AXP2101.
6. Только затем добавить кириллический шрифт и локализацию строк с визуальными тестами.
7. Оптимизировать энергопотребление, пробуждение и безопасное сохранение.

**Важное:** текущий `deploy.sh` рассчитан на оригинальную IPS-плату. Нельзя считать драйвер AMOLED интегрированным, пока не добавлены код, проверки и подтверждение запуска на V1.
