# Как участвовать в разработке MedveGoshi

Спасибо за интерес к русскоязычной версии [Capigoshi](https://github.com/rjcaubit/capigoshi).

## Куда отправлять изменения

- Ошибки, идеи, вопросы об оборудовании — через [Issues MedveGoshi](https://github.com/Medvedolog/medvegoshi/issues).
- Большие изменения (новая плата, логика игры, файловый формат) сначала обсудите в Issue.
- Язык документации и пользовательского интерфейса — **русский**; публичные идентификаторы Python и имена файлов не переводим ради совместимости. Английские комментарии и PR допустимы.
- За основу берётся ветка `main`. Изменения отправляйте отдельными небольшими Pull Request.

## Что реально поддерживается

- **Waveshare ESP32-S3-Touch-LCD-1.83 / ST7789 + CST816D:** исходная платформа игры.
- **Waveshare ESP32-S3-Touch-AMOLED-1.8 V1 / SH8601 + FT3168:** цель портирования, пока не проверена.
- **AMOLED 1.8 V2:** другая ревизия, совместимость не гарантируется.

Не объявляйте драйвер, прошивку или режим энергосбережения рабочим без подтверждения на реальной плате. Для проектов с детьми не добавляйте скрытую телеметрию, обязательную регистрацию или опасные действия с аккумулятором.

## Среда и тесты

Понадобятся Python 3, MicroPython для компьютера, Pillow, mpremote и esptool.

```bash
python3 -m pip install pillow mpremote esptool
cd previa
micropython rodar.py
python3 montar.py
cd ..
python3 -m unittest discover -s companion/testes -t .
python3 -m companion.sim.aceite todos
```

`previa/rodar.py` выполняет настоящую игровую логику с имитацией оборудования. После изменений графики просмотрите результаты `previa/png/`, особенно листы `_folha_*.png`. При изменении нейросети запускайте также её unit- и acceptance-тесты. Если тест не запускается в вашей среде, укажите причину в PR вместо ложной отметки о прохождении.

## Слои проекта

- `main.py` — цикл игры и взаимодействие.
- `vida.py` — поведение и реплики, **без прямой работы с экраном и железом**.
- `desenho.py` — отрисовка; не смешивайте её с логикой поведения.
- `hw.py` — драйверы и периферия. Для AMOLED лучше отделить реализацию от публичного API.
- `companion/` — обучение, сохранение мозга, симулятор.
- `rede.py` и `portal.py` — сеть и интерфейс смартфона.

Дополнительные сведения в [CODEMAP.md](CODEMAP.md).

## Правила локализации

1. Сначала вынесите видимые строки в таблицу локализации; затем добавьте переключение `ru/en`, а не заменяйте внутренние ключи и имена команд.
2. Для русского текста предусмотрите шрифт с кириллицей — `framebuf.text()` сам по себе её не рисует.
3. Проверяйте обрезание надписей и попадание кнопок: исходные размеры рассчитаны на 240×284.
4. Учитывайте маленьких детей: доступные подписи, без внезапного сброса питомца; критичные операции с подтверждением.
5. Не добавляйте в прошивку приватные Wi-Fi-пароли и персональные данные.

## Новые персонажи

Персонажи с детскими рисунками — основа проекта. Изучите `desenho.py` (например `cachorro()`, `sapinho()`), таблицы `ELENCO`, `NOMES`, высоты `HTOP` и `FRASES_CHAR` в `vida.py`. Предусмотрите выражения глаз и рта, состояние болезни, масштабирование и тест превью.

Не публикуйте фотографии, имена и другие данные детей без надлежащего разрешения.

## Звук

Используйте только собственные или разрешённые к распространению записи, например CC0 и CC-BY (при условии указания авторства). Исходный формат игры: **raw PCM 16 кГц, 16 бит, стерео**.

```bash
ffmpeg -i input.wav -ar 16000 -ac 2 -f s16le sons/example.raw
```

Файлы Pixabay нельзя автоматически включать в репозиторий: прочитайте [CREDITOS.md](CREDITOS.md).

## Pull Request

Опишите цель, изменённые файлы, проверенные тесты, аппаратную ревизию и оставшиеся ограничения. Для экранных изменений приложите снимки превью или фотографии устройства. Сохраняйте [лицензию MIT](LICENSE), уведомления об авторстве и отдельные ограничения на сторонние изображения и аудио.
