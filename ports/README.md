# Waveshare AMOLED 1.8 V1 — экспериментальный порт

**Статус: первый этап реализован в едином PR #2; железа нет,
аппаратная проверка не выполнялась. Не готовая прошивка.**

Только V1: SH8601 + FT3168. **Не устанавливать на V2 CO5300/CST820.**

## Что сделали

- `ports/amoled_v1.py`: независимый аппаратный мост, который ожидает
  нативный драйвер MicroPython `amoled.QSPIPanel/AMOLED`. Он не заменяет
  основную IPS-реализацию `hw.py`.
- Временная совместимая область 240 × 284 в центре физического
  экрана 368 × 448: **x=64..303**, **y=82..365**.
  Сохраняются размеры, русский шрифт и меню оригинальной игры;
  чёрные поля пока остаются вокруг. Позднее — масштабирование UI.
- `FT3168Touch.ler()` читает I²C 0x38 и переводит касания физических
  пикселей в игровые координаты. Пустые поля и отпускание игнорируются.
  За кадр выполняется одно чтение; краткий импульс GPIO21 не используется
  как признак удержания пальца. NACK в простое не прерывает тест.
- Защита по I²C: **0x20 TCA9554**, **0x38 FT3168** и запрет при
  обнаружении **0x15 CST820**. При холодном старте FT3168 может
  удерживаться в reset, тогда разрешение отпустить его допускается
  только с явной опцией `verified_v1=True` после проверки маркировки.
- Управление панелью/сенсором через TCA9554:
  **EXIO0 — reset SH8601, EXIO1 — питание AMOLED, EXIO2 — reset тача**.
  Остальные биты регистров сохраняются.
- Пример `ports/amoled_v1_smoke.py` — отдельная ручная проверка
  цветных полос и сенсора, **не вызывается игрой автоматически**.
- `ports/preview_amoled_v1.py` — компьютерный предпросмотр именно
  временного 1:1 отображения, не эмуляция чипа.
- `tests/test_amoled_v1.py` — имитация QSPI, сенсора, TCA9554,
  проверка соответствия координат, байтов RGB565 и отказ при V2.

## Разводка V1

| Функция | Контроллер или вывод |
|---|---|
| Экран | SH8601, QSPI 368×448 |
| Тач | FT3168, I²C 0x38 |
| Экспандер | TCA9554, I²C 0x20 |
| I²C SCL/SDA | GPIO14 / GPIO15 |
| QSPI CS/CLK | GPIO12 / GPIO11 |
| QSPI DATA0..3 | GPIO4 / GPIO5 / GPIO6 / GPIO7 |
| Touch IRQ | GPIO21 |
| LCD RESET / AMOLED POWER / TP RESET | TCA9554 EXIO0 / EXIO1 / EXIO2 |
| GPIO13 | НЕ считать аппаратным LCD_RESET без отдельного подтверждения |

Источник: [официальная Waveshare](https://docs.waveshare.com/ESP32-S3-Touch-AMOLED-1.8),
[собственный конфиг дободу](https://github.com/dobodu/Lilygo_Waveshare_Amoled_Micropython/blob/main/examples/config/WS_180_AMOLED.py),
[отладка V1 и проверка TCA9554 на оборудовании](https://github.com/rbirkby/waveshare-touch-amoled-1.8-fluidparticles).
В стороннем MicroPython-примере GPIO13 используется как reset;
другой источник, проверенный на оборудовании, указывает на EXIO0.
Поэтому текущий экспериментальный мост использует **EXIO0** и оставляет
вопрос окончательной совместимости нативного драйвера открытым.
Код внешней библиотеки не копировался; у неё лицензия MIT.

## Почему V1 пока нельзя прошить обычным установщиком

SH8601 требует QSPI-транспорт (четыре линии данных). Обычный драйвер
ST7789 и обычная версия MicroPython с `machine.SPI` не заменяют
нативный QSPI-стек. Экспериментальный бинарник с модулем `amoled` [собран](https://github.com/Medvedolog/medvegoshi/actions/runs/45073840851), но не проверен на физической V1.

`install.sh --board amoled-v1` по-прежнему намеренно отказывает.
Нельзя использовать IPS `deploy.sh` для V1, чтобы не стереть и не
испортить заводскую прошивку. Для первого теста когда-нибудь потребуется
подтверждённая V1 и точная сборка стороннего нативного драйвера.

## Память — расчёт, не измерение

- 240×284×2 = **136 320 байт** для штатного `framebuf` игры;
- 368×448×2 = **329 728 байт** для полного нативного RGB565 буфера
  (если выбранная реализация драйвера его выделяет);
- крупный режим дополнительно выделяет один **320 160-байтовый** выходной
  буфер 368×435 и таблицы координат; буфер повторно используется между кадрами;
- три буфера вместе, если нативный драйвер выделяет весь framebuffer панели:
  **786 208 байт**, без накладных расходов, памяти DMA, Zoo, аудио и мозга.
  Физических замеров PSRAM/FPS пока нет.

## Нативная сборка MicroPython с SH8601/QSPI — воспроизводимый прототип

Добавлена отдельная [сборка GitHub Actions](https://github.com/Medvedolog/medvegoshi/actions/workflows/build-amoled-v1.yml).
Она **не прошивает плату**, не меняет IPS и не публикует релиз.
При успешной компиляции появляется артефакт `medvegoshi-v1-native-UNTESTED`
с согласованными `medvegoshi-amoled-v1-experimental.bin` и
`medvegoshi-v1-app-UNTESTED.zip`, общим `SHA256SUMS`,
`BUILD-METADATA.json` и лицензиями. BIN содержит MicroPython без игры;
игровые файлы лежат отдельно в ZIP. Сборка на одном коммите проверяет
каждый файл ZIP и компилирует каждый .py закреплённым `mpy-cross`
для ESP32-S3. Успешная сборка не подтверждает работу на плате.

Зафиксированные источники:

- MicroPython [v1.28.0, SHA `e0e9fbb17ed6fd06bb76e266ae554784c9c80804`](https://github.com/micropython/micropython/tree/e0e9fbb17ed6fd06bb76e266ae554784c9c80804);
- ESP-IDF [v5.5.2](https://github.com/espressif/esp-idf/tree/v5.5.2), Docker
  `espressif/idf:v5.5.2` с зафиксированным индексом SHA256;
- MIT-драйвер [dobodu/Lilygo_Waveshare_Amoled_Micropython, SHA `97934b7c35b1720a14fd69e4e1322bb5684b9b2c`](https://github.com/dobodu/Lilygo_Waveshare_Amoled_Micropython/tree/97934b7c35b1720a14fd69e4e1322bb5684b9b2c).

Скрипты `ports/build_amoled_v1.sh` и `ports/prepare_firmware.py` скачивают
названные исходники по **точным коммитам**. Последний корректирует
некорректный CMake-файл нативного модуля в отдельной временной копии,
подключает `schrift.c` и включает схему **Flash 16 МБ / Octal PSRAM**.
В наши исходники не импортирован сторонний графический C-код.
Любые изменения расположения файлов или лицензии upstream прерывают сборку.

На Linux с установленным ESP-IDF 5.5.2 (или внутри одноимённого Docker
image) воспроизвести сборку можно командой:

```bash
bash ports/build_amoled_v1.sh
```

Обычные проверки выполняются без компилятора ESP32:

```bash
python3 -m unittest discover -s tests -p 'test_amoled_native_build.py'
```

**Подключение полной игры** реализовано через отдельный ручной профиль.
Графический smoke `ports/v1_game_demo.py` остаётся самостоятельным и
показывает Жирафика без загрузки сохранений или полного игрового цикла.

## Интерактивный тест V1, отдельно от игры

Тестовый вход не запускает `main.py`, не читает и не меняет игровые
сохранения и не перепрошивает устройство. В окне 240×284 он рисует
настоящего Жирафика, отмечает тач и считает нажатия BOOT и короткие
нажатия PWR. PWR отображается как N/A, если прошивка не включила его
событие: тест не настраивает питание и не включает IRQ. Долго PWR не
удерживать. Опциональный Wi‑Fi лишь читает состояние уже существующего
STA; не включает радио, не сканирует эфир и не подключается.

**Без платы:** из корня репозитория с Pillow:

```sh
python -m ports.emulate_v1 --out build/v1-bringup.png
python -m ports.emulate_v1 --wifi --out build/v1-bringup-wifi.png
python -m unittest discover -s tests -p 'test_*v1*.py'
```

Эмулятор прогоняет тот же тестовый вход и графику, подставляя
сымитированные FT3168/BOOT/AXP2101 и проверяя окно, длину и байты
передачи RGB565. Растеризация отдельных фигур и ASCII на компьютере
приближённая. Это не эмуляция ESP32, MicroPython или электрических
сигналов, и не доказательство работы на плате.

**На физической V1:** только из REPL на уже подготовленном совместимом
MicroPython с нативным `amoled` и файлами проекта, после сверки
маркировки V1. Не запускать на V2 и не использовать установщик.
Тест по умолчанию длится около 12 секунд плюс время отрисовки; отчёт
возвращается в REPL.

```python
from ports.v1_bringup import run
print(run(confirmed_v1=True))
# Лишь прочитать состояние существующего STA:
# print(run(confirmed_v1=True, wifi_status=True))
```


### Проверка готовности к полному запуску V1

`ports/v1_game_hal.py` проверяет фактические ответы RTC, IMU, PMIC и
аудиокодека, после явного подтверждения V1. Всё ещё без записи в
регистры. Присутствие устройства не считается подтверждением его
работы: `require_game_hal` дополнительно требует отдельной проверки
экрана, тача, аудио и корректной работы игры с RTC без записи.
Этот модуль и тестовый экран сами игру не запускают.


### Native Pip в экспериментальной сборке

Сборка включает отдельный модуль `pip_native` с ядром характера и
PCM-синтезом голоса Пипа. Файлы игры по-прежнему не включены в BIN.
Интеграция игры опциональна (настройка `"pip_native": true`, только
Пип в режиме «Уход» и на обычных часах). Она сохраняет C-состояние в его
отдельном слоте и не заменяет поведение Жирафика или других питомцев.

При обычной позе оригинальный C-рисовальщик Пипа готовит небольшой
отдельный RGB565-буфер глаз, который накладывается на тело. С переворотом,
поворотом, отсутствующим нативным API или сторонним спрайтом остаётся
обычный рендерер. Память ограничена размерами буфера, аудио не является
русской речью: это оригинальные эмоциональные звуки.

В ручном профиле V1 можно явно подать экспериментальный
`amoled_v1_audio.make_audio`: для Пипа он передаёт PCM оригинального
синтезатора в ES8311. По умолчанию звук выключен, драйвер микрофона в
эту версию не включён. Питание динамика держится выключенным до
буферизации тишины и выключается при завершении/ошибке. Полярность,
реальный такт I²S и акустические артефакты ещё не подтверждены на плате.

### Полный игровой цикл без платы

```sh
python -m ports.v1_full_game_emulate --out build/v1-full-game.png
python -m unittest discover -s tests -p 'test_v1_full_game_emulate.py'
```

Этот тест на CPython запускает штатный `main.principal()` с Жирафиком,
прогоняет кормление через FT3168, открывает меню свайпом и закрывает его
кнопкой BOOT. Кадры проходят через тот же адаптер и в эмулированный
буфер SH8601. RTC, IMU, звук и питание здесь заменены заглушками,
сеть запрещена, а сохранения живут только во временной папке.
Тест не запускает прошивку MicroPython и не подтверждает работу железа.


### Ручной профиль полного приложения V1

`ports/amoled_v1_launch.py` требует два явных подтверждения и принимает
только подтверждённый профиль `amoled_1_8_v1`. Для него приложение
должно быть подготовлено как `v1_game_app.py`, **не** установленным
`main.py` автозапуска. Используйте только пару BIN + ZIP из одного
артефакта. До инициализации аппаратного профиля и чтения сохранений
запуск проверяет API нативных модулей и все исходники по индексу,
хеш которого встроен в BIN. Несовместимая прошивка, изменённый или
отсутствующий файл блокируют запуск. Никакое действие не прошивает плату.
Локальные часы проверяются при запуске и читаются без записи; пустой
RTC не подменяется выдуманной датой. По умолчанию Wi-Fi выключен и
кнопка PWR не опрашивается. При явном разрешении Wi-Fi профиль использует
существующий `wifi.json` и не открывает точку настройки, не перезагружает
устройство и не меняет часы через NTP. Сохранённый автономный режим
блокирует включение радио до ручного переключения. У IPS остаётся прежний запуск.

Ручной вход V1 по умолчанию выбирает `screen_mode="large"`: вид 368×435
с полями 6 и 7 пикселей сверху и снизу. `screen_mode="1:1"` оставляет
диагностические 240×284. Координаты тача рассчитываются по той же таблице
соответствия, что и пиксели. Игра остаётся пиксельной; текст полностью
меню настроек рисуется в выходном разрешении пропорциональным Noto Sans
с фиксированной базовой линией, сглаживанием краёв и цифрами равной
ширины. Открытие, закрытие и появление системного сообщения не меняют
шрифт. На IPS масштабирования нет.

### Сверка с исходниками платы

- **Экран SH8601:** [официальный BSP V1](https://github.com/waveshareteam/Waveshare-ESP32-components/blob/c77caf968fa6b11f3b6a416c853c578d012a8cea/bsp/esp32_s3_touch_amoled_1_8/esp32_s3_touch_amoled_1_8.c#L377-L419)
  использует [настройку QSPI 40 МГц](https://github.com/waveshareteam/Waveshare-ESP32-components/blob/310ccc681289046194f6a1aa7489bf157761888b/display/lcd/esp_lcd_sh8601/include/esp_lcd_sh8601.h#L96-L110),
  вместо прежних 80 МГц. [Пример Waveshare](https://github.com/waveshareteam/ESP32-S3-Touch-AMOLED-1.8/blob/01fd3200370a4417b257e8a4c185a04ef931342a/examples/arduino/examples/02_Drawing_board/02_Drawing_board.ino#L34-L61)
  подтверждает reset через EXIO0; удерживаем его при включении EXIO1, не циклируя
  питание. Патч к [dobodu](https://github.com/dobodu/Lilygo_Waveshare_Amoled_Micropython/blob/97934b7c35b1720a14fd69e4e1322bb5684b9b2c/amoled/amoled_qspi_bus.c#L75-L153)
  поднимает CS и сообщает об ошибках команды, RAMWR и передачи пикселей.
- **Тач FT3168:** контроллер и разводка подтверждены Waveshare. Если тач
  не отвечает и маркировка V1 уже подтверждена, держим EXIO2 в reset 20 мс
  и ждём 80 мс после отпускания по [таблице 3-5 FT3168](https://files.waveshare.com/wiki/common/FT3168.pdf#page=11).
  Регистр идентификатора 0xA0 не стал новым обязательным условием.
- **Звук ES8311:** [схема Waveshare](https://files.waveshare.com/wiki/ESP32-S3-Touch-AMOLED-1.8/ESP32-S3-Touch-AMOLED-1.8.pdf)
  подтверждает усилитель NS4150B и GPIO46. Его [даташит](https://datasheet.lcsc.com/lcsc/2209161630_Shenzhen-Nsiway-Tech-NS4150B_C189961.pdf#page=3)
  указывает типичный запуск за 120 мс (не гарантию максимума); драйвер
  теперь ждёт 150 мс без остановки игры, с заглушённым ЦАП, до подачи звука.
- **Wi-Fi:** вызовы сверены с [MicroPython WLAN](https://github.com/micropython/micropython/blob/e0e9fbb17ed6fd06bb76e266ae554784c9c80804/ports/esp32/network_wlan.c#L214-L269)
  и [ESP-NOW](https://github.com/micropython/micropython/blob/e0e9fbb17ed6fd06bb76e266ae554784c9c80804/ports/esp32/modespnow.c#L510-L543).
  Необязательная диагностика Wi-Fi создаёт WLAN и инициализирует
  драйвер, но сама не включает интерфейс и не запускает сканирование.
  Запросы погоды синхронные, перегруженная очередь ESP-NOW также может
  задержать кадр. Звук и Wi-Fi сначала испытывать отдельно.

Этот путь проверяется на ПК тем же `main.principal()` через временные
сохранения и настоящие адаптеры с имитацией железа. Сценарий
`--scenario switch` кормит двух питомцев через тач, переключает их в
меню и проверяет сохранения:

```sh
python -m ports.v1_full_game_emulate --screen-mode large --scenario switch --out build/v1-return.png --pip-out build/v1-pip.png
python -m ports.v1_full_game_emulate --scenario switch --native-pip --out build/v1-pip-c.png
```

Вторая команда использует оригинальное ядро характера на настольном C,
но не выполняет код MicroPython/ESP32. Перед снятием блокировки нужны
отдельные физические проверки экрана, тача, RTC, IMU, PWR, питания и звука
на экземпляре с маркировкой V1. Не запускать на V2, IPS или на пользовательской
плате без резервной копии.

Пакет исходников для будущей ручной проверки можно собрать **на ПК**:

```sh
python -m ports.package_amoled_v1_app --output build/MEDVEGOSHI-V1-APP-UNTESTED.zip
```

ZIP воспроизводимый и содержит контрольные суммы и только перечисленные
файлы приложения, без бинарника, прошивки, конфигурации Wi-Fi и сохранений.
В ZIP не будет `main.py` или `boot.py`, а `v1_game_app.py` откажется
запускаться без уже выбранного профиля V1. Пакет не является установщиком. Отдельно подготовленный ZIP предназначен
для просмотра и проверки на ПК: само устройство примет его только при
точном совпадении с индексом в BIN. Файлы игры не следует смешивать
с остатками другой сборки и сторонними модулями.
