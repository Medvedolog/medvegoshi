# Zoo Registry v1 — подключаемые питомцы без правок игрового движка

**Статус:** экспериментальная реализация в ветке `feature/zoo-plugin-registry`.
Это продолжение Жирафика (PR #6). Исходные 10 персонажей Capigoshi
сохраняются без изменений, Пип и Жирафик перенесены на единый ABI.

**Главное:** новая папка `zoo/animals/<id>/` обнаруживается **при следующей
загрузке** игры. В новом релизе не надо менять `main.py`, `desenho.py`
или `vida.py` для каждого нового животного. Перезапуск обязателен:
система намеренно не перечитывает файловую систему на каждом кадре.

## 1. Формат плагина

```text
zoo/
  registry.py                  # единственный реестр питомцев
  animals/
    __init__.py
    pip/
      __init__.py
      manifest.json
      face.py                  # адаптер прежнего Пипа
    girafa/
      __init__.py
      manifest.json
      face.py                  # адаптер прежнего Жирафика
    your_new_animal/           # будущий сторонний герой
      __init__.py
      manifest.json
      face.py                  # собственная процедурная графика
  packs/
    your_new_animal/
      manifest.json            # НЕОБЯЗАТЕЛЬНЫЙ пакет RGB565
      normal.rgb565
      normal.mask
```

**Один новый питомец = одна папка из трёх файлов.** Существующие
`zoo/pip/face.py` и `zoo/giraffe/face.py` оставлены для обратной
совместимости; их адаптеры в `zoo/animals/` подчиняются общему ABI.
Новые животные не обязаны импортировать старые модули.

Пример `manifest.json` для **тестового** лисёнка (не включённого в
штатную прошивку):

```json
{
  "schema": 1,
  "id": "fox",
  "name_ru": "Лисёнок",
  "htop": 65,
  "head": -44,
  "top": -68,
  "half": 25,
  "eyes": [[-10, -52], [10, -52]],
  "thermometer": [26, -40],
  "ring": [90, 60, 35],
  "license": "MIT",
  "author": "Автор оригинальной графики",
  "source_url": "https://example.org/your-own-repository",
  "phrases": {
    "ocioso": ["Привет!", "Идём играть!"],
    "carinho": ["Ура!", "Погладь меня!"]
  }
}
```

Замените пример URL реальным HTTPS-адресом и укажите **действительного
автора и проверенную лицензию**. Факт наличия `MIT` в манифесте не
доказывает наличие прав на чужие изображения.

Координаты `head`, `top`, `eyes`, `thermometer` заданы относительно
точки опоры ног `(0, 0)`: отрицательные `y` направлены **вверх**.
`half` — половина ширины для взаимодействия и анимаций,
`htop` — высота оригинального персонажа в игровых формулах.

### API `face.py`

```python
def render(E, R, P, A, eyes="normal", mouth="sorriso", sick=False):
    E(0, -35, 25, 28, (240, 155, 80), True)  # эллипс
    E(-10, -50, 4, 5, (255, 255, 255))
    E(10, -50, 4, 5, (255, 255, 255))
    return ((-10, -50), (10, -50))            # две точки глаз
```

Движок сам передаёт функции `E` (эллипс), `R` (прямоугольник),
`P` (многоугольник), `A` (дуга), рассчитывает масштаб/трансформацию,
состояния глаз/рта, фазы жизни и расположение термометра.
Функция рисования возвращает **ровно две относительные координаты глаз**.

Вызов `render` следует делать без доступа к `main.py`, `hw.py`,
состоянию мозга и сохранениям; плагин не должен самостоятельно
переключать питомца или вести файловую запись. Новый персонаж получает
режимы «Уход», «Жизнь», «Гулять» и тот же мозг автоматически.
При ошибке модульного художника движок возвращается к встроенной Капи.

## 2. Автоматический реестр

`zoo/registry.py` реализует:

- `BUILTINS` — неизменяемый порядок первых **10** исходных ID.
- `discover(root)` — ограниченное сканирование каталогов со строгой
  проверкой имён, манифеста, расположения `face.py` и `__init__.py`.
- `ELENCO`, `NOMES`, `HTOP`, `EXTRA_PHRASES` — единый результат,
  который читает и рендерер `desenho.py`, и поведение `vida.py`.
- `renderer(id)` — поздняя загрузка нужного `zoo.animals.<id>.face`,
  без импорта всех зверей при запуске.
- `refresh()` — обновление снимка реестра для последующей
  **перезагрузки** игры (сам по себе вызов не обновляет уже импортированные
  значения `desenho.ELENCO` / `vida.NOMES`).

Неверный, частично скопированный или слишком большой манифест
**не включает** животное в выбор. Проверяются длина русских реплик
(до двух строк по 14 символов), обязательные сведения об авторе,
лицензия и безопасное ASCII-имя пакета. Явно запрещено
затенять любую из десяти исходных записей.

Внутренний ID: только `[a-z][a-z0-9_]*` (не более 40 символов),
имя `name_ru` — не более 14 символов. Число одновременно обнаруженных
плагинов ограничено 12, чтобы не перегружать ESP32 и меню.
Пип и Жирафик остаются в установленном порядке выбора.

## 3. Установка на оригинальную IPS

Обновить само ядро с поддержкой реестра можно **только на исходной IPS**.
Проверяйте порт и используйте **обновление файлов**, а не очистку Flash:

```bash
sh install.sh --board ips --port /dev/ttyACM0 --files-only
```

Скрипт `deploy.sh` автоматически обходит локальные папки
`zoo/animals/*` и копирует в MicroPython **только**
`__init__.py`, `face.py` и `manifest.json`, причём манифест —
последним. Для следующего героя его менять не придётся.

Альтернативная установка одной новой папки, **без перепрошивки**:

```bash
python3 -m zoo.tools.install_animal \
  --source zoo/animals/fox \
  --port /dev/ttyACM0 --board ips --dry-run

python3 -m zoo.tools.install_animal \
  --source zoo/animals/fox \
  --port /dev/ttyACM0 --board ips
```

`--source` может указывать на подготовленную внешнюю папку плагина.
На устройстве предварительно должна находиться прошивка с `registry.py`.
После передачи **перезагрузите игрушку** для повторного сканирования.
Никакие пользовательские `capi.json`, `brain.bin` и `config.json`
установщик плагинов не стирает.

**Добавление нового животного не равно переключению активного героя.**
В меню Capigoshi подтверждённая смена питомца по-прежнему начинает жизнь
с яйца и заменяет активное состояние. Для сохранения текущего питомца
не подтверждайте переключение до резервного копирования.
Не удаляйте папку **активного** животного: исходная логика при отсутствии
ID переключает сессию на Капи, а данные в `capi.json` — общий файл.
**Сейчас есть безопасное отключение только неактивного модуля** через `zoo/tools/disable_animal.py` с обязательным архивом `config.json`, `capi.json` и плагина. Отсутствующий активный модуль больше не превращается молча в Капи — вместо этого игра показывает USB-восстановление и прекращает запись.
**Безопасное удаление/миграция активного питомца и транзакционное обновление остаются в TODO.** Подробности: [RECOVERY_RU.md](RECOVERY_RU.md).

**AMOLED V1 не поддерживается**; оба установщика должны возвращать
ошибку, пока аппаратный SH8601/FT3168-порт не испытан.

### Спрайты для внешнего плагина

Если новый герой находится не внутри клона репозитория, сначала
установите его через `install_animal.py`, затем при установке скина
передайте дополнительный путь ко всем локальным плагинам:

```bash
python3 -m zoo.tools.install_pack --pack /tmp/fox-ips \
  --animals-root /path/to/my-animals \
  --board ips --port /dev/ttyACM0 --dry-run
```

В каталоге `/path/to/my-animals/fox` должны находиться три проверяемых
файла, а в манифесте спрайта — ровно тот же `id`.
`--animals-root` только уточняет список разрешённых ID на компьютере
и **не устанавливает сам плагин**. На ESP32 животное нужно сначала
установить и проверить отдельно.

## 4. Спрайты — отдельный, необязательный слой

Если у питомца есть проверенный RGB565-пакет в
`/zoo/packs/<id>/`, `desenho.personagem` сначала пробует его.
Иначе автоматически вызывает процедурный `face.py`, а при аварии
плагина использует Капи.

Ранее созданный конвертер и runtime loader из PR #4/#5 **сохраняются**.
Для PNG-ассетов обязательны отдельные права, manifest и SHA256:
[конвейер спрайтов](tools/README.md). Так можно ставить и
нового персонажа, и различные его облики, не переписывая игровой цикл.

## 5. Тесты и ограничения

```bash
python3 -m unittest discover -s zoo/tests -p 'test_plugin_registry.py'
python3 -m unittest discover -s zoo/tests -p 'test_*.py'
sh tests/test_installer.sh
```

`test_plugin_registry.py` создаёт на компьютере **временного 13-го
персонажа** и в отдельном процессе запускает настоящий
`desenho.personagem()` и `vida.py` без изменения этих файлов.
Проверяет обнаружение, речь, имя, высоту, отрисовку, запрет конфликтующих
ID, неверный JSON/файл и `--dry-run` инсталлятора.
