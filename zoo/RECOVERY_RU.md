# MedveGoshi — защита питомца и восстановление Zoo (IPS)

> **Статус:** реализовано и проверено хостовыми тестами в единой ветке
> `feature/russian-game-ui`. На физической IPS пока не проверено.
> **AMOLED 1.8 V1 не поддерживается.**

## 1. Почему понадобилась защита

Capigoshi использует **единый** `capi.json` для текущего питомца.
Раньше при отсутствии выбранного внешнего героя строка
`cfg['personagem'] = 'capi'` молча подменяла его на Капи. Последующее
сохранение могло перезаписать данные активного питомца.

Теперь при чтении `config.json` и `capi.json` применяется
`zoo/recovery.py`. Если выбранный ID Zoo отсутствует, config повреждён,
JSON питомца обрезан или его поля имеют неверные типы, загрузка
**останавливается до входа в игровой цикл и до записи сохранений**.
На IPS появляется русское сообщение о восстановлении через USB.
Первый запуск с отсутствующими `config.json` и `capi.json` по-прежнему
возможен: это штатное состояние новой платы.

Сама защита **не восстанавливает повреждённые данные автоматически**;
она лишь не даёт игре их затереть. При сохранённой корректной копии
можно вернуть файлы через USB.

## 2. Если появился экран «НЕТ ПИТОМЦА»

1. **Не стирайте Flash и не запускайте обычную полную установку.**
   В режиме IPS **без** `--files-only` установщик делает `erase_flash`.
2. Подключите устройство к USB и скопируйте сохранения на компьютер.
   Установите `python3 -m pip install mpremote` на компьютере.
3. Верните каталог нужного героя, чей ID показан на экране.
   Например, для Жирафика каталог `zoo/animals/girafa/`.
4. Перезапустите плату. `registry.py` обнаружит животное при загрузке,
   конфигурация снова укажет на прежний ID. Если `capi.json` цел,
   возраст и показатели останутся прежними.

Пример резервного копирования, когда порт `/dev/ttyACM0`:

```bash
mkdir -p medvegoshi-backup
mpremote connect /dev/ttyACM0 cp :config.json medvegoshi-backup/config.json
mpremote connect /dev/ttyACM0 cp :capi.json medvegoshi-backup/capi.json
# Дополнительные файлы мозга, если существуют:
mpremote connect /dev/ttyACM0 cp :brain.bin medvegoshi-backup/brain.bin
mpremote connect /dev/ttyACM0 cp :brain.bak medvegoshi-backup/brain.bak
```

Последние две команды могут выдавать ошибку, если файл мозга
ещё не создавался. На Windows замените порт на `COM5` и используйте
папку без уже существующих чужих копий.

Для восстановления исходного собственного Жирафика из рабочей ветки:

```bash
python3 -m zoo.tools.install_animal \
  --source zoo/animals/girafa \
  --board ips --port /dev/ttyACM0 --dry-run

python3 -m zoo.tools.install_animal \
  --source zoo/animals/girafa \
  --board ips --port /dev/ttyACM0
```

После восстановления выполните перезапуск устройства.

Если экран показывает «ОШИБКА НАСТРОЕК» или
«ОШИБКА СОХРАНЕНИЯ», сначала сохраните повреждённые файлы на компьютер.
Восстановите `config.json` или `capi.json` **из собственной проверенной
копии**. Не заменяйте данные заглушкой, не очищайте общий файл питомца,
не меняйте ID вручную без осознания последствий.

## 3. Безопасное отключение НЕАКТИВНОГО плагина

```bash
python3 -m zoo.tools.disable_animal \
  --id pip --board ips --port /dev/ttyACM0 \
  --backup-dir ./backup-disabled-pip-001 --dry-run

python3 -m zoo.tools.disable_animal \
  --id pip --board ips --port /dev/ttyACM0 \
  --backup-dir ./backup-disabled-pip-001
```

Каталог резервной копии должен **не существовать** до выполнения.
При реальном запуске утилита читает с ESP32 `config.json` и
`capi.json`, копирует манифест, `face.py`, `__init__.py` и по возможности
`brain.bin`/`brain.bak`, проверяет JSON и лицензионный манифест.

**Если `config.json` указывает на отключаемого питомца, операция
запрещена.** Нельзя отключать десять исходных героев. Нельзя отключать
плагин без успешного резервного копирования. `--dry-run` не обращается
к устройству, поэтому **не определяет**, активен ли питомец: полная
проверка делается только при реальном запуске.

Для неактивного героя удаляется **только**
`zoo/animals/<id>/manifest.json`, его `face.py` и `__init__.py`
остаются на плате; `config.json`, `capi.json`, `brain.bin` не
изменяются. После перезагрузки модуль исчезает из меню; для возврата
достаточно вернуть сохранённый `manifest.json` на устройство и
перезапустить.

## 4. Порядок копирования при обновлении IPS

`deploy.sh` сначала копирует библиотеки, `zoo/registry.py`,
`zoo/recovery.py`, файлы персонажей и компоненты мозга, а
**`main.py` записывает последним, непосредственно перед перезапуском**.
Это уменьшает вероятность установки нового игрового ядра без его
зависимостей. Однако такой способ **не является атомарным обновлением
всей прошивки**: при обрыве передачи есть риск смешения версий.
Перед обновлением рекомендуется создать резервные копии.

Обновление уже установленной оригинальной IPS:

```bash
sh install.sh --board ips --port /dev/ttyACM0 --files-only
```

Обычная команда без `--files-only` стирает все сохранения.
На AMOLED V1 ничего не прошивать.
