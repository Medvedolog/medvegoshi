# Установка MedveGoshi на две аппаратные платформы

Русскоязычная игровая логика MedveGoshi — **общая** для обеих целевых плат. Отличия дисплея, сенсора, пинов и питания должны находиться в аппаратном профиле, а не в копиях `main.py`, `vida.py` или `companion/`.

## Текущая совместимость

| Профиль | Плата | Дисплей и сенсор | Установка |
|---|---|---|---|
| `ips` | Waveshare ESP32-S3-Touch-LCD-1.83 | ST7789, 240×284; CST816D | **Доступна**: исходная платформа, русские строки в PR #2 |
| `amoled-v1` | Waveshare ESP32-S3-Touch-AMOLED-1.8 V1 | SH8601, 368×448; FT3168 | **Заблокирована** до появления работающего драйвера |
| `amoled-v2` | AMOLED 1.8 V2 | CO5300; CST820 | Не целевая ревизия; не поддерживается |

Фраза «доступна» для IPS означает наличие исходного аппаратного пути и нового установщика с русской прошивкой; фактические результаты работы на устройстве пока не проверены. Наличие рабочего исходного Capigoshi на IPS не заменяет испытание русской версии после изменения шрифтов.

## Установка и обновление IPS

Для macOS/Linux установите `esptool`, `mpremote`, Python 3. Подключите именно **IPS 1,83″**. Узнать последовательный порт можно в списке USB-устройств; он отличается в зависимости от операционной системы.

Проверить выбор платы, ничего не записывая:

```sh
sh install.sh --board ips --port /dev/ttyACM0 --dry-run
```

Чистая прошивка (полностью сотрёт сохранения):

```sh
sh install.sh --board ips --port /dev/ttyACM0
```

Только обновить файлы **на уже работающей IPS-плате**, сохранив питомца и обученную нейросеть:

```sh
sh install.sh --board ips --port /dev/ttyACM0 --files-only
```

Для входа в режим полной прошивки: удерживайте **BOOT**, кратко нажмите **RST**, затем отпустите BOOT. При обновлении только файлов устройство должно работать в обычном режиме.

Старые команды `bash deploy.sh` и `bash deploy.sh --so-arquivos` остаются поддержанными и всегда означают **IPS**. Новая обёртка `install.sh` просто явным образом выбирает профиль; в настоящий момент она не определяет модель подключённой платы автоматически.

## Почему AMOLED пока нельзя прошить

```sh
sh install.sh --board amoled-v1
```

Команда завершится ошибкой без обращения к устройству. Это сделано специально: `deploy.sh` до сих пор инициализирует IPS-дисплей ST7789 и сенсор CST816D, а AMOLED V1 требует SH8601 + FT3168 и другой инициализации питания.

После завершения порта обе команды будут доступны, но **один и тот же набор русских игровых файлов** должен запускаться с двумя независимыми аппаратными реализациями. Без подтверждения на физической AMOLED V1 эту ветку нельзя считать готовой.

## Контракт будущих профилей

- `main.py`, `vida.py`, `desenho.py`, `font_ru.py`, `companion/` — общая логика, графика и язык.
- `ips` — ST7789, CST816D, исходные настройки GPIO, штатная прошивка MicroPython.
- `amoled-v1` — SH8601, FT3168, аппаратная конфигурация Waveshare V1 и совместимая сборка MicroPython.
- Установщик обязан **отказывать** при выборе неизвестного/неподдерживаемого профиля.
- Сохранения `config.json`, файлы питомца и `brain.bin` не должны получать несовместимые форматы из-за выбора экрана.

См. также [план переноса AMOLED V1](https://github.com/Medvedolog/medvegoshi/blob/docs/russian-first/docs/PORT_AMOLED_V1.md) и [план локализации](https://github.com/Medvedolog/medvegoshi/blob/docs/russian-first/docs/LOCALIZATION_RU.md) из PR #1 (до объединения с `main`). Благодарность оригинальному проекту [Capigoshi](https://github.com/rjcaubit/capigoshi).
