# Zoo / sprite pipeline: PNG → RGB565 + 1-bit mask

**Статус:** P0 — хостовый конвертер и **первый IPS runtime-загрузчик**
`zoo/sprites.py` (в ветке `feature/zoo-sprite-runtime`). Доступны
построчное чтение RGB565, 1-битная маска, SHA256-проверка кадра и
возврат к процедурной графике при ошибках. **На реальном ESP32 пока не
испытывалось; FPS, расход памяти и стабильность Flash предстоит измерить.**
AMOLED V1 остаётся неподдерживаемым на уровне прошивки.

Методика вдохновлена Giraffegotchi ([clean_art.py](https://github.com/elliotboney/giraffegotchi/blob/440a9545f5447c32cf48b8cb93f6258fbd842d13/tools/clean_art.py),
[prep_sprite.py](https://github.com/elliotboney/giraffegotchi/blob/440a9545f5447c32cf48b8cb93f6258fbd842d13/tools/prep_sprite.py)).
Реализация конвертера написана заново для MedveGoshi; код этих двух
скриптов не копировался.

## Подготовка на компьютере

Понадобятся Python 3.10+ и Pillow:

```bash
python3 -m pip install "Pillow>=10,<13"
```

Сделайте **свой** набор кадров с прозрачностью:

```text
my-pet-source/
  pack.json
  happy.png
  sad.png
  sleeping.png
```

Пример `pack.json`, **не пригоден без замены исходных данных на настоящие**:

```json
{
  "id": "my_pet",
  "name_ru": "Мой питомец",
  "author": "Автор изображений",
  "license": "CC0-1.0",
  "source_url": "https://example.org/author-owned-images",
  "source_commit": "0123456789abcdef0123456789abcdef01234567",
  "rights_confirmed": false,
  "source_anchor": [48, 95],
  "anchors": {
    "sleeping": [48, 95]
  }
}
```

**Перед конвертацией** нужно подтвердить право на каждый PNG и поставить
`rights_confirmed: true`; без этого конвертер прекращает работу.
Это не автоматическая проверка лицензии: значение устанавливает тот,
кто проверил право использования. `source_commit` — настоящий полный SHA
коммита со входными картинками, а не строка из примера.
В этом прототипе допускаются `MIT`, `CC0-1.0` и `CC-BY-4.0`;
обязательны реальный автор и URL.

`source_anchor` — координата одной и той же анатомической точки
питомца (например, стопы) на исходных кадрах. Можно задать отличающуюся
точку для отдельных кадров через `anchors`, как для спящего питомца.
Все кадры будут уменьшены с **одним общим коэффициентом**, выровнены
по этим точкам и уложены в единое логическое поле.

## Сборка

```bash
python3 zoo/tools/build_sprites.py   --source /path/to/my-pet-source   --out /tmp/my-pet-ips   --size 96x112 --target ips --fps 4

python3 zoo/tools/build_sprites.py   --source /path/to/my-pet-source   --out /tmp/my-pet-amoled   --size 160x192 --target amoled-v1 --fps 4
```

Флаг `--target amoled-v1` означает **формат ресурса** для будущего
порта, **не поддержку AMOLED-платы установщиком**.

**Для установки на сегодняшнюю игру** `id` должен совпадать с существующим
ID персонажа из `desenho.ELENCO` (`cachorro`, `capi`, `pip` и т. д.).
Пример `my_pet` выше показывает формат, но его нельзя установить до
регистрации нового животного в игре.

Результат:

```text
my-pet-ips/
  manifest.json
  happy.rgb565
  happy.mask
  sad.rgb565
  sad.mask
  sleeping.rgb565
  sleeping.mask
```

Дополнительные параметры: `--margin 4`, `--max-kib 768`,
`--overwrite` (пересобрать **только** ранее созданный и не
содержащий посторонних файлов каталог). Исходные PNG не меняются
и не перезаписываются.

## Бинарный формат v1

- `*.rgb565`: **2 байта на пиксель**, RGB565,
  **big-endian** (красный пиксель = `f8 00`).
- `*.mask`: **1 бит на пиксель**, строки идут слева направо,
  сверху вниз, старший бит байта — первый пиксель. Значение **1** — непрозрачный;
  значение **0** — прозрачный. В RGB565 на прозрачных пикселях записан ноль.
- Полупрозрачность упрощается порогом alpha ≥128. Смешивание с
  фоном на ESP32 не требуется.
- `manifest.json`: ID, имя, права, исходный commit SHA,
  ширина/высота, опорная точка, FPS, целевой профиль, для каждого кадра —
  относительный путь, SHA256 от конкатенации RGB565+mask, размер и границы.
- Порядок кадров: сортировка PNG по имени; время сборки и абсолютные пути
  **не записываются**, поэтому выход детерминированный.
- Максимум 64 кадра; исходный PNG максимум 1024×1024,
  целевой кадр 8…256 px по каждой оси. Размер всего набора ограничен
  флагом `--max-kib` (по умолчанию 768 КиБ).

**Важно:** RGB565 big-endian — канонический формат пакета.
При работе с драйверами дисплеев, ожидающими другой порядок байтов,
аппаратный адаптер обязан корректно преобразовывать их при отправке.
Сам конвертер не должен тайно менять порядок байтов для IPS/AMOLED.

## Предпросмотр на компьютере

```bash
python3 zoo/tools/preview_sprites.py --pack /tmp/my-pet-ips \
  --out /tmp/preview-ips.png --frame happy --board ips

python3 zoo/tools/preview_sprites.py --pack /tmp/my-pet-amoled \
  --out /tmp/preview-amoled.png --frame happy --board amoled-v1
```

Это **графический предпросмотр** ресурсов на фоне 240×284 или 368×448,
а не симуляция драйвера дисплея или подтверждение аппаратной совместимости.

## Установка необязательного пакета на IPS

Перед установкой **используйте существующий ID** персонажа, например
`"id": "cachorro"` для альтернативного облика Карамельки, и соберите
`--target ips`. Пакет дополняет выбранного героя, а не создаёт новый
игровой ID. Исходные персонажи остаются встроенными в прошивку.

```bash
python3 zoo/tools/install_pack.py --pack /tmp/my-pet-ips \
  --board ips --port /dev/ttyACM0 --dry-run
python3 zoo/tools/install_pack.py --pack /tmp/my-pet-ips \
  --board ips --port /dev/ttyACM0
```

Укажите реальный порт устройства; на Windows это может быть `COM5`.
Понадобится `mpremote`: `python3 -m pip install mpremote`.

**Установщик не стирает прошивку и сохранения.** Он проверяет
SHA256, размеры, формат, ID и атрибуцию; затем переносит бинарные кадры
в `/zoo/packs/<id>/`, отправляя `manifest.json` последним.
Смена набора файлов **не атомарна**, поэтому загрузку следует проводить,
когда игрушка не выполняет игровой цикл. После копирования **перезагрузите
IPS-плату**, чтобы очистить кеш списка пакетов.

Пакет необязателен: нет каталога — работает оригинальная процедурная
графика. Повреждённый/неправильно собранный пакет не должен ломать игру,
а возвращает штатный рисунок. Во время анимаций, требующих растяжения
или вращения, пока сохраняется исходный рендерер, чтобы не сломать движения.
Яйцо и возрастные декоративные эффекты сохраняются в штатном игровом коде.

**Важно:** `--board amoled-v1` на этом этапе всегда отказывает. Переключения
скинов через меню ещё нет: чтобы отключить ресурс, нужно удалить
`/zoo/packs/<id>/` через файловую консоль и перезапустить устройство.
Без реальной проверки на плате нельзя считать функцию готовой к релизу.

## Устройство загрузчика

`zoo/sprites.py` проверяет манифест, размер каждого файла и контрольную
сумму SHA256 **перед первым использованием каждого кадра**. Для отрисовки
читает одну строку RGB565 и маску **только текущего кадра**. На IPS
использует `framebuf.blit` по строкам; при отсутствии `blit` есть
медленный попиксельный путь для тестов. Кадры `*.rgb565` не хранятся
целиком в оперативной памяти.

В `desenho.personagem()` вызывается необязательная отрисовка; если
возвращён `None`, вызывается исходный художник. Состояние питомца,
`brain.bin` и игровой цикл не изменяются.

## Автоматические проверки

```bash
python3 -m unittest discover -s zoo/tests -p "test_sprite*.py"
python3 -m unittest discover -s zoo/tests -p "test_renderer_integration.py"
```

Тесты сами создают оригинальные небольшие PNG в `tempfile`;
**никакие чужие изображения для CI не нужны**. Проверяются
байтовая воспроизводимость, маска, RGB565, выравнивание,
хеши кадров, ограничения объёма, разрешения и защита
от удаления исходников.
