# План переноса MedveGoshi на AMOLED 1,8″ V1

**Статус:** первый этап программного порта подготовлен в [ports/amoled_v1.py](../ports/amoled_v1.py): V1-контракт QSPI, FT3168, TCA9554, временное окно 240×284, mock-тесты. **Это не готовая прошивка игры, не проверено на плате.** AMOLED V1 по-прежнему блокируется штатным установщиком. [Подробности и результаты](../ports/README.md).

## Целевое устройство

- **Waveshare ESP32-S3-Touch-AMOLED-1.8 V1**
- ESP32-S3R8, 8 МБ PSRAM, 16 МБ Flash;
- AMOLED 368×448, контроллер **SH8601** (QSPI);
- сенсор **FT3168** (I²C);
- QMI8658 (IMU), PCF85063 (RTC), ES8311 (звук), AXP2101 (питание);
- встроенные микрофон, динамик, кнопки BOOT/PWR и подключение Li-ion.

**Не путать с V2:** CO5300/CST820. Упаковка и рекламные фотографии могут показывать старую ревизию — сверяйте реальную плату.

## Исходная программная база

[Capigoshi](https://github.com/rjcaubit/capigoshi) и этот форк изначально используют `hw.Tela` для **ST7789 240×284** и `hw.Toque` для **CST816D**. Перенос требует заменить аппаратный слой, не ломая публичный интерфейс `main.py` и `desenho.py`.

Для драйвера SH8601 под MicroPython есть внешний проект [dobodu/Lilygo_Waveshare_Amoled_Micropython](https://github.com/dobodu/Lilygo_Waveshare_Amoled_Micropython); см. его [пример конфигурации Waveshare 1,8″](https://github.com/dobodu/Lilygo_Waveshare_Amoled_Micropython/blob/main/examples/config/WS_180_AMOLED.py). Это **отдельный проект**, его код пока не включён в прошивку. До интеграции необходимо проверить лицензию, API, версию MicroPython и поддержку конкретной платы.

## Выполнено на компьютере — первый этап

- Реализован отдельный модуль `ports/amoled_v1.py` с контрактом
  `Tela.fb`/`mostrar()`/`brilho()` и `FT3168Touch.ler()`.
  Модуль зависит от нативного MicroPython-драйвера `amoled` с
  `QSPIPanel`, которого **пока нет** в распространяемой прошивке MedveGoshi.
- Для первого шага сохраняется старый логический холст 240×284 в
  центре AMOLED 368×448 (отступы x=64, y=82). В этом режиме русское
  меню и область касаний сохраняют прежнюю геометрию.
- V1 Touch: FT3168 на I²C `0x38`, Touch IRQ на GPIO21.
  Touch RESET идёт через TCA9554 EXIO2: до отпускания reset
  обычное сканирование I²C может не найти `0x38`.
  Для изменения аппаратного reset требуется явное подтверждение
  ревизии V1 по маркировке.
- Физический reset панели на TCA9554 EXIO0, питание — EXIO1.
  Переносить IPS GPIO reset/power нельзя. Первоначальный сторонний
  конфиг MicroPython содержит отличающуюся привязку GPIO13;
  это оставлено отдельным пунктом аппаратной приёмки.
- V2 Touch CST820 на `0x15` приводит к отказу до отправки кадров.
  Это начальная программная защита, а не исчерпывающая автоматическая
  идентификация платы.
- Появились тесты `tests/test_amoled_v1.py` и визуализация
  `qa-amoled-v1/v1-viewport-240x284.png` в GitHub Actions.

**В отличие от предварительного плана, драйвер SH8601 здесь ещё
не собран/не включён в MicroPython.** Основной `main.py` пока не
переключается на новый порт; `install.sh --board amoled-v1` запрещён.

## Этап сборки нативного SH8601 — экспериментально

В одной рабочей ветке создана [отдельная GitHub Actions сборка](../.github/workflows/build-amoled-v1.yml)
с фиксированными версиями MicroPython **v1.28.0**, ESP-IDF **v5.5.2**
и [MIT-модуля QSPI SH8601](https://github.com/dobodu/Lilygo_Waveshare_Amoled_Micropython).
Скрипт [build_amoled_v1.sh](../ports/build_amoled_v1.sh)
получает исходники по конкретным commit SHA, исправляет повреждённый
CMake upstream в отдельной копии, добавляет недостающее `schrift.c`
и выбирает 16 МиБ Flash / Octal PSRAM.

Успешный workflow должен публиковать **только экспериментальный**
MicroPython бинарник и SHA256, **без файлов MedveGoshi и без прошивки**.
До успешного workflow утверждать, что бинарник собран, **нельзя**.
Даже при успешной компиляции это `hardware-NOT_TESTED`,
не релиз для конечного пользователя.

Первое подключение к общему игровому рендереру находится в
[ports/v1_game_demo.py](../ports/v1_game_demo.py): используется
настоящий `desenho.personagem('girafa')` из MedveGoshi без второй
копии игры. Полноценное исполнение `main.py` на V1 остаётся
не реализованным до переноса звука, RTC, IMU и PMIC.

## Этапы портирования

### 1. Проверить реальную ревизию

Сверить контроллеры, разводку, GPIO, тип и ёмкость Flash/PSRAM, наличие аккумулятора и реакцию кнопок. Подключить USB-C, получить консоль MicroPython. Не начинать с массовой заливки всего `deploy.sh`.

### 2. Поднять дисплей

Инициализировать SH8601 по QSPI на V1 с корректной последовательностью включения питания. Проверить ориентацию, цвета RGB565, очистку экрана, частичный и полный вывод, яркость и выключение панели. Зафиксировать используемые версии драйвера/прошивки.

### 3. Поднять сенсор FT3168

Прочитать касания по I²C, проверить нормировку координат и ориентацию относительно AMOLED. Прогнать касание, удержание, перетаскивание и жест открывания меню. Нельзя считать сенсор рабочим только потому, что AMOLED показывает картинку.

### 4. Сохранить API исходной игры

Предусмотреть совместимые методы `Tela.fb` / `Tela.mostrar()`, `Toque.ler()`, `Movimento.forca_g()`, `Relogio`, `Som`, `Bateria`. Изолировать разные аппаратные профили IPS/AMOLED вместо глобальной замены всего `hw.py`.

### 5. Переработать рендерер

Оригинал рисует в координатах 240×284 и использует маленький шрифт 8×8. На 368×448 нужно выбрать проверяемую стратегию:

- либо изначально выводить 240×284 в центральной области без искажения;
- либо масштабировать с контролем областей касаний и безопасных зон;
- затем адаптировать меню, надписи и иллюстрации к нативному разрешению.

На первом этапе приоритет **совместимость игры**, затем улучшение внешнего вида.

### 6. Звук и датчики

Протестировать ES8311, реальные каналы ввода/вывода и маршрутизацию аудио, QMI8658, RTC, питание AXP2101. Нельзя автоматически переносить GPIO оригинальной IPS-платы.

### 7. Энергосбережение

Отдельно реализовать отключение AMOLED, безопасное сохранение состояния, режим сна ESP32-S3, пробуждение, восстановление часов и игровой логики. Измерять ток в активном режиме, с погашенным экраном и во сне на реальном аккумуляторе. **Автономность пока неизвестна**.

### 8. Русский интерфейс и испытания

Локализация — в отдельной таблице строк. Для кириллицы нужен совместимый шрифт, с тестами длины фраз и переноса строк. Проверить с ребёнком управление, читаемость и отсутствие случайного сброса данных.

## Минимальный набор приёмочных проверок

- Экран загружается после холодного старта и программного сброса; изображение без сдвига и битых цветов.
- Нажатия, удержание, перетаскивание и меню корректно соотносятся с пикселями.
- Игровой цикл не блокируется при воспроизведении звука.
- Уход, наблюдение, прогулка, возраст, часы и основные реакции работают.
- Состояние питомца и `brain.bin` переживают нормальное выключение/включение.
- Режим сна и зарядка не приводят к порче данных; автономность измерена.
- Все тесты `previa/` и `companion/testes/` проходят или известные отклонения документированы.

## Правила безопасности изменений

Ветка `main` остаётся стабильной до проверки. Не объявляйте экспериментальный образ совместимым с V1 без испытаний. Оригинальный IPS-профиль и путь восстановления должны быть сохранены.

Благодарность за исходный код игры — [rjcaubit/capigoshi](https://github.com/rjcaubit/capigoshi).

### Отдельная проверка микрофона, динамика и microSD (не запуск игры)

В экспериментальном парном пакете есть два ручных теста. Они не
запускаются при импорте, не включают Wi‑Fi, не трогают сохранения
и не снимают блокировку установщика. Статус: **проверены на имитации,
не проверены на физической плате**. Использовать только на явно
опознанной V1, после подготовки штатного бэкапа, из свободного REPL,
без запущенной игры и других владельцев I²S/SDMMC.

```python
from machine import I2C, Pin
from ports import amoled_v1_voice_smoke, amoled_v1_sd_smoke

bus = I2C(0, scl=Pin(14), sda=Pin(15), freq=400_000)
# При появлении приглашения произнесите короткую фразу.
print(amoled_v1_voice_smoke.run(bus, enabled=True, confirmed_v1=True,
                               duration_ms=2000))
# Отдельно, если вставлена карта:
print(amoled_v1_sd_smoke.probe(bus, enabled=True, confirmed_v1=True))
```

Если тач не отвечает, тесты остановятся без попытки его сброса; сначала
пройдите проверку V1 по этой инструкции. Звуковой тест пишет только в
RAM (до двух секунд), выключает приём перед включением воспроизведения,
держит усилитель выключенным во время записи и восстанавливает состояние
линии питания микрофона. Ненулевой сигнал не означает разборчивую речь:
результат должен подтвердить оператор. SD-тест только читает геометрию и
сектор 0 через SDMMC 1-bit, не монтирует и не форматирует карту.

Источники: [XiaoZhi V1](https://github.com/78/xiaozhi-esp32/tree/a31349491ba9805c5e7b7f7b4dc6f33172cdc655/main/boards/waveshare/esp32-s3-touch-amoled-1.8)
(разводка микрофона, ALDO1, усилитель; не переносим общую настройку PMIC
и зарядки), [Espressif ES8311](https://github.com/espressif/esp-bsp/blob/fb5714e02cf4289d6f092f817a7ef1e0b72a49ed/components/es8311/es8311.c)
(настройки аналогового входа), [Waveshare V1 pin_config](https://github.com/waveshareteam/ESP32-S3-Touch-AMOLED-1.8/blob/01fd3200370a4417b257e8a4c185a04ef931342a/examples/arduino/libraries/Mylibrary/pin_config.h)
(аудио и SDMMC). В отличие от XiaoZhi текущий MicroPython не выводит
MCLK через `machine.I2S`; используем тот же вариант BCLK и 32-битных
слотов, что в существующем драйвере воспроизведения. На реальной V1
нужно проверить уровень, разборчивость и отсутствие пропусков, а затем
отдельно совместную работу экрана, звука и Wi‑Fi.
